# Високосные секунды

Документация встроенной таблицы високосных секунд в `gnss-time`, политики
обновления и расширения во время выполнения.

## Источник данных

Все данные взяты из бюллетеня IERS C:
<https://hpiers.obspm.fr/iers/bul/bulc/Leap_Second.dat>

**Последняя проверка:** бюллетень IERS C 70 (декабрь 2024) — до июня 2025
новых високосных секунд не запланировано.
**Текущее состояние (май 2026):** TAI − UTC = 37 с, без изменений с
2017-01-01.

## Что такое високосная секунда

TAI (Международное атомное время) — непрерывная атомная шкала времени.
UTC — гражданское время, которое удерживается в пределах 0,9 с от UT1
(астрономического времени) за счёт периодической вставки **високосных секунд**.

При вставке UTC «останавливается» на одну секунду — существует момент
`23:59:60 UTC`, тогда как GPS продолжает идти непрерывно. Разность `TAI − UTC`
увеличивается на 1.

GPS никогда не вставляет и не пропускает секунды: `GPS = TAI − 19 с`
(фиксировано с 1980-01-06). Поэтому для конвертации GPS ↔ UTC необходимо
знать текущую разность `TAI − UTC`.

## Формат таблицы

Каждая запись — это `(tai_nanos_threshold, tai_minus_utc)`:

- `tai_nanos_threshold` — наносекунды TAI (относительно GPS), начиная с
  которых действует новое значение (включительно, нижняя граница)
- `tai_minus_utc` — значение `TAI − UTC` в целых секундах, начиная с этого
  порога

### Формула вычисления порога

```text
tai_nanos = (unix_event_timestamp − GPS_EPOCH_UNIX + tai_minus_utc) × 10⁹
```

где `GPS_EPOCH_UNIX = 315 964 800` (секунды времени Unix).

Пример для 2017-01-01 (`unix = 1 483 228 800`, `n = 37`):

```text
gps_s     = 1_483_228_800 − 315_964_800 = 1_167_264_000
threshold = (1_167_264_000 + 37) × 10⁹  = 1_167_264_037_000_000_000
```

## Политика обновления таблицы

IERS публикует бюллетень C дважды в год (в январе и июле). Каждый выпуск
сообщает:

- будет ли добавлена новая високосная секунда в ближайшие 6 месяцев, или
- подтверждает, что изменений нет.

### Когда обновлять

Если IERS объявляет новую високосную секунду:

1. **Вычислите порог** по формуле выше, используя метку времени Unix
   события.
2. **Добавьте запись** в конец массива `BUILTIN_TABLE` в
   `src/tables/leap_seconds.rs`:

   ```rust
   // ГГГГ-ММ-ДД: TAI−UTC → N
   LeapEntry::new(<threshold>, <N>),
   ```

3. **Обновите комментарий `// Last verified:`** в том же файле.
4. **Обновите заголовок этого документа** (`LEAP_SECONDS.ru.md`).
5. **Запустите тесты** — проверки на этапе компиляции в `leap_seconds.rs`
   автоматически подтверждают упорядоченность и монотонность:

   ```bash
   cargo test
   cargo check --target thumbv7em-none-eabihf
   ```

6. **Обновите `CHANGELOG.md`** и выпустите патч-версию крейта.

### Автоматические проверки корректности таблицы

В `src/tables/leap_seconds.rs` определены три `const`-проверки (assertions),
которые срабатывают во время **компиляции** (а не только при тестировании):

| Проверка                  | Что проверяется                                         |
| ------------------------- | ------------------------------------------------------- |
| `_ASSERT_FIRST_ENTRY`     | `tai_nanos == 0`, `tai_minus_utc == 19`                 |
| `_ASSERT_TABLE_INVARIANTS`| строгая упорядоченность и инкремент +1 по всей таблице  |
| `_ASSERT_LAST_ENTRY`      | последняя запись соответствует 2017-01-01, `n == 37`    |

Если вы добавите запись с неверным порогом или пропустите инкремент,
компилятор отклонит её **немедленно**, не запуская тестов.

> **Важно:** при добавлении новой записи вы должны обновить
> `_ASSERT_LAST_ENTRY` — измените ожидаемые значения `tai_nanos` и
> `tai_minus_utc`.

## Использование встроенной таблицы

```rust
use gnss_time::{LeapSeconds, gps_to_utc, LeapSecondsProvider};
use gnss_time::{Time, Gps, Tai};

// Встроенная таблица: покрывает все события эры GPS до 2017-01-01
let ls = LeapSeconds::builtin();

// Диагностика: когда произошло последнее событие?
let last = ls.last_update().unwrap();

assert_eq!(last.as_nanos(), 1_167_264_037_000_000_000); // 2017-01-01

// Текущее значение TAI−UTC
assert_eq!(ls.current_tai_minus_utc(), 37);

// Конвертация GPS → UTC
let gps = Time::<Gps>::from_seconds(1_167_264_018); // 2017-01-01 GPS
let utc = gps_to_utc(gps, &ls).unwrap();
```

## Обновление в рантайме для embedded / приёмника

Для GNSS-приёмников, которые загружают таблицу из навигационного сообщения
или альманаха, используйте `RuntimeLeapSeconds`:

```rust
use gnss_time::{LeapEntry, RuntimeLeapSeconds, LeapSecondsProvider};

// Начинаем со снимка встроенной таблицы на этапе компиляции
let mut rt = RuntimeLeapSeconds::from_builtin();

// Приёмник сообщает новую секунду из альманаха
// (гипотетическое событие — только для иллюстрации)
// rt.try_extend(LeapEntry::new(threshold_ns, 38)).unwrap();

// Используется в тех же местах, что и LeapSeconds::builtin()
let gps = gnss_time::Time::<gnss_time::Gps>::from_seconds(1_000_000);
let utc = gnss_time::gps_to_utc(gps, &rt).unwrap();
```

### API `RuntimeLeapSeconds`

| Метод                     | Описание                                        |
| ------------------------- | ----------------------------------------------- |
| `from_builtin()`          | Создаёт таблицу из снимка на этапе компиляции   |
| `from_slice(&[LeapEntry])`| Создаёт из произвольного среза (slice)          |
| `try_extend(entry)`       | Добавляет новую запись с проверкой              |
| `last_update()`           | Момент TAI последнего события                   |
| `current_tai_minus_utc()` | Текущее значение TAI−UTC                        |
| `len()` / `is_empty()`    | Размер таблицы                                  |
| `entries()`               | Все записи в виде среза                         |

### Проверка при `try_extend`

`try_extend` отклоняет недопустимые записи:

```rust
use gnss_time::{LeapEntry, LeapExtendError, RuntimeLeapSeconds};

let mut rt = RuntimeLeapSeconds::from_builtin();

// Ошибка: порог не возрастает строго
let err = rt.try_extend(LeapEntry::new(0, 38)).unwrap_err();

assert_eq!(err, LeapExtendError::NotStrictlyAscending);

// Ошибка: инкремент не равен 1
let err = rt.try_extend(LeapEntry::new(9_999_999_999_000_000_000, 99)).unwrap_err();

assert_eq!(err, LeapExtendError::NonUnitIncrement);
```

## Собственный провайдер

Для полного контроля реализуйте трейт `LeapSecondsProvider`:

```rust
use gnss_time::{LeapSecondsProvider, Tai, Time};

/// Провайдер с фиксированным значением (например, для тестов).
struct FixedOffset(i32);

impl LeapSecondsProvider for FixedOffset {
    fn tai_minus_utc_at(&self, _tai: Time<Tai>) -> i32 {
        self.0
    }
}

let provider = FixedOffset(37);
```

## Будущие високосные секунды и их отмена

В таблице нет записей после 2017-01-01. Для более поздних моментов
библиотека возвращает `TAI − UTC = 37` (последнее известное значение) —
стандартный подход «предполагаем, что новых високосных секунд не будет».

**Статус отмены:** на Всемирной конференции радиосвязи 2022 года (WRC-22)
было принято решение прекратить вставку високосных секунд **не позднее
2035 года**. До этого срока текущая таблица остаётся действительной. После
2035 года конвертация UTC ↔ GPS станет полностью детерминированной (как
сегодня GPS ↔ TAI).
