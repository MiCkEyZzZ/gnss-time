# Основы времени GNSS

Практическое руководство по системам времени GNSS для разработчиков программного обеспечения.

## Почему время в GNSS — это сложно

В большинстве программ время — это одно понятие. Вы вызываете `now()`,
получаете число, и это число означает одно и то же везде.

В GNSS это не так.

Каждая спутниковая навигационная система поддерживает свои собственные
независимые часы. Эти часы начинаются в разные календарные даты, привязаны
к разным стандартам и со временем накапливают разные целочисленные смещения.
Один и тот же физический момент в реальном мире имеет разное числовое
значение в зависимости от того, какую систему вы спрашиваете.

Это не особенность, которую можно «замаскировать». Ошибка означает, что метки
времени вашего приёмника отличаются на 14, 18 или 19 секунд — и вы даже не
заметите этого.

## Четыре шкалы времени, которые нужно понимать

### TAI — Международное атомное время

TAI (Temps Atomique International) — основа всех современных систем измерения
времени.

- Поддерживается усреднением ~450 атомных часов по всему миру
- Не содержит високосных секунд — абсолютно равномерная шкала
- Эпоха: **1958-01-01 00:00:00**
- Все системы GNSS привязаны к TAI фиксированным или вычисляемым смещением

TAI — **опорная шкала** для всех конвертаций в этой библиотеке. Любая
конвертация между шкалами GNSS внутри проходит через TAI.

### UTC — Всемирное координированное время

UTC — это то, что показывает ваши настенные часы (приблизительно).

- UTC поддерживается близко к UT1 (вращению Земли)
- Когда вращение Земли замедляется, добавляется **високосная секунда**
- UTC = TAI − N, где N — число вставленных високосных секунд
- По состоянию на 2017 год: **TAI − UTC = 37 секунд**

Високосные секунды объявляются организацией IERS заранее (примерно за
6 месяцев). Формулы для их предсказания не существует — нужна таблица.

### Время GLONASS

GLONASS — российская навигационная система.

- Эпоха: **1996-01-01 00:00:00 UTC(SU)** = 1995-12-31 21:00:00 UTC
- GLONASS ведёт отсчёт по **UTC(SU)** — российской реализации UTC, равной
  UTC + 3 часа (московское время), **но содержащей високосные секунды**
- Поскольку GLONASS синхронизирован с UTC, конвертация GLONASS ↔ UTC — это
  просто сдвиг эпохи: **+757 371 600 секунд**
- Таблица високосных секунд для GLONASS ↔ UTC не нужна
- Но она **нужна** для GLONASS ↔ GPS / Galileo / BeiDou

### Время GPS

GPS — американская навигационная система.

- Эпоха: **1980-01-06 00:00:00 UTC**
- Смещение: **GPS = TAI − 19 секунд** (фиксированное, без високосных секунд)
- В момент эпохи GPS был синхронизирован с UTC, когда TAI − UTC = 19 с
- В GPS никогда не вставлялись високосные секунды — время идёт непрерывно
- По состоянию на 2017 год: **GPS опережает UTC на 18 секунд**

GPS-приёмники передают текущее смещение GPS–UTC в навигационных сообщениях,
чтобы можно было вычислить гражданское время.

### Время Galileo

Galileo — европейская навигационная система.

- Эпоха: **1999-08-22 00:00:00 UTC** (неделя GPS 1024, TOW 0)
- Смещение: **Galileo = TAI − 19 секунд** — идентично GPS
- Наносекундная метка Galileo и GPS с одинаковым значением **обозначает один
  и тот же физический момент**
- Конвертация GPS ↔ Galileo — тождество: числовое значение наносекунд не
  меняется

### Время BDS

BDT — китайская навигационная система.

- Эпоха: **2006-01-01 00:00:00 UTC**
- Смещение: **BDT = TAI − 33 секунды**
- Так как GPS = TAI − 19 с, получаем: **BDT = GPS − 14 секунд**
- Эта разница в 14 секунд фиксирована и никогда не изменится

## Проблема високосных секунд

Високосные секунды — самая сложная часть работы со временем GNSS.

### Что такое високосная секунда?

Когда вращение Земли замедляется, UTC начинает опережать UT1 (солнечное
время). Чтобы удерживать разницу в пределах 0,9 секунды, IERS иногда вставляет
**положительную високосную секунду**:

Часы UTC показывают **23:59:60**, прежде чем перейти на **00:00:00**.

Отрицательные високосные секунды (удаление секунды) теоретически возможны,
но никогда не применялись.

### Как GPS обрабатывает високосные секунды

В GPS нет високосных секунд. Время просто растёт.

Когда в UTC вставляется високосная секунда, разница GPS–UTC увеличивается на 1.

До 1981-07-01 разница составляла 0 с. После 2017-01-01 она составляет
18 секунд.

| Событие     | TAI − UTC | GPS − UTC |
| ----------- | --------- | --------- |
| 1980-01-06  | 19 с      | 0 с       |
| 1981-07-01  | 20 с      | 1 с       |
| ...         | ...       | ...       |
| 1999-01-01  | 32 с      | 13 с      |
| 2017-01-01  | 37 с      | 18 с      |

GPS-приёмники передают текущее смещение GPS–UTC (поле `IODC`), чтобы
программное обеспечение могло вычислить гражданское время.

### Секундное окно неоднозначности

В момент вставки високосной секунды существует окно в 1 секунду, в котором
одной и той же метке GPS соответствуют два значения UTC:

```zsh
GPS: 1_167_264_017 нс  →  UTC: 23:59:59  (последняя секунда перед високосной)
GPS: 1_167_264_018 нс  →  UTC: 23:59:60  (вставленная високосная секунда)
GPS: 1_167_264_018 нс  →  UTC: 00:00:00  (начало следующего дня — то же значение GPS!)
```

Эта библиотека обнаруживает окно и сигнализирует о нём через
`ConvertResult::AmbiguousLeapSecond`.

## Граф конвертации

```text
                    ┌──────────────────────────────────────────────┐
                    │           TAI (reference scale)              │
                    │  T_tai = T_self + OFFSET_TO_TAI              │
                    └──────┬──────┬───────┬──────┬─────────────────┘
                           │      │       │      │
               fixed +19s  │      │+19s   │+33s  │  contextual
                           ▼      ▼       ▼      │
                          GPS   Galileo  BeiDou  │
                           │      │       │      │
                           │ identity fixed      │
                           │                     ▼
                           │               UTC ←──── GLONASS
                           │               │  epoch shift
                           └───────────────┘
                            contextual (needs the leap-second table)
```

Фиксированные конвертации (високосные секунды не требуются):

- GPS ↔ TAI, GPS ↔ Galileo, GPS ↔ BeiDou
- Galileo ↔ BeiDou, Galileo ↔ TAI, BeiDou ↔ TAI
- GLONASS ↔ UTC

Контекстные конвертации (требуется `LeapSecondsProvider`):

- GPS ↔ UTC, GPS ↔ GLONASS
- Galileo ↔ UTC, Galileo ↔ GLONASS
- BeiDou ↔ UTC, BeiDou ↔ GLONASS

## Частые ошибки

### Использование GPS как UTC

```rust
// НЕПРАВИЛЬНО — после 2017 года GPS опережает UTC на 18 секунд
let gps = Time::<Gps>::from_seconds(gps_seconds_from_receiver);
let civil_time = gps.as_seconds(); // ← это секунды GPS, а не UTC!
```

```rust
// ПРАВИЛЬНО
let utc = gps.into_scale_with(LeapSeconds::builtin()).unwrap();
let civil_seconds = utc.as_seconds(); // секунды UTC с 1972-01-01
```

### Игнорирование високосных секунд при GPS → UTC

```rust
// НЕПРАВИЛЬНО — предполагается фиксированная разница в 18 секунд
let utc_seconds = gps.as_seconds() - 18;
```

```rust
// ПРАВИЛЬНО — используется полная таблица високосных секунд
let utc = gps.into_scale_with(LeapSeconds::builtin()).unwrap();
```

### Смешивание шкал времени в арифметике

```rust
// НЕПРАВИЛЬНО — в gnss-time не скомпилируется, но это частая ошибка:
// let delta = gps_time - glonass_time;
```

```rust
// ПРАВИЛЬНО — сначала преобразовать к одной шкале
let glo_as_utc: Time<Utc> = glonass.into_scale().unwrap();
let gps_as_utc: Time<Utc> = gps.into_scale_with(ls).unwrap();
let delta = gps_as_utc - glo_as_utc;
```
