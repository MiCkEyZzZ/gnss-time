# Инварианты и гарантии безопасности

В этом документе перечислены инварианты, которые соблюдает `gnss-time`,
а также механизмы, которые их обеспечивают.

## Инварианты на уровне типов

### I-1: Изоляция доменов

Значения `Time<A>` и `Time<B>` (где `A ≠ B`) нельзя смешивать в
арифметических выражениях.

**Обеспечение:** система типов Rust. Реализации `Sub<Time<S>>` и
`Add<Duration>` существуют только для `Time<S>` с одним и тем же `S`. Любая
попытка вычесть метку времени GLONASS из метки времени GPS приводит к ошибке
компиляции.

### I-2: Нет неявных конвертаций

Между разными шкалами нет реализаций `From` / `Into`. Каждая конвертация
выполняется явно через вызов `into_scale()` или `into_scale_with(ls)`.

**Обеспечение:** отсутствие blanket-реализаций. Все реализации
`IntoScale` / `IntoScaleWith` написаны вручную и проверены.

### I-3: Запечатанные шкалы времени

Внешний код не может реализовать `TimeScale`. Набор допустимых шкал:
`{Gps, Glonass, Galileo, Beidou, Tai, Utc}`.

**Обеспечение:** паттерн «запечатывающего» (sealed) супертрейта
`private::Sealed`. Трейт `Sealed` находится в приватном модуле и не имеет
публичного пути.

## Арифметические инварианты

### I-4: Нет тихого переполнения

Все операторы `+` и `-` для `Time<S>` и `Duration` вызывают панику при
переполнении. Для кода, где паника неприемлема, предусмотрены
checked-/saturating-/fallible-варианты.

**Обеспечение:** обёртывающая (wrapping) арифметика не используется. Линт
`#[deny(arithmetic_overflow)]` (через `-D warnings` в CI) ловит случайные
переполнения ещё на этапе компиляции. `#[allow(arithmetic_overflow)]` в CI
запрещён.

### I-5: `u64::MAX` — жёсткий предел

`Time::<S>::MAX.as_nanos() == u64::MAX`. Ни одна операция не может создать
значение больше этого; вместо этого она либо вызывает панику, либо
возвращает `None`, либо насыщается, либо возвращает `Err`.

**Обеспечение:** вся арифметика выполняется в `i128` с проверкой диапазона
перед обратным приведением к `u64`.

### I-6: `Duration` — знаковый

`Duration` использует наносекунды в `i64`. Вычитание более поздней метки
времени из более ранней даёт отрицательное значение `Duration`. Это
позволяет естественно работать в обоих направлениях.

## Инварианты конвертации

### I-7: TAI — универсальная центральная точка (pivot)

```text
T_tai = T_self + S::OFFSET_TO_TAI
```

Это уравнение выполняется для всех шкал с фиксированным смещением (`Gps`,
`Galileo`, `Beidou`, `Tai`). Все парные конвертации выводятся из этой
формулы. Никакой «магии» для отдельных пар шкал нет.

**Обеспечение:** `try_convert<T>` вызывает `to_tai()`, а затем
`T::from_tai()`. Ни одна конвертация не обходит TAI.

### I-8: Тождество GPS–Galileo

У GPS и Galileo одинаковое смещение
`OFFSET_TO_TAI = 19_000_000_000 нс`. Поэтому `T_gps.as_nanos() == T_gal.as_nanos()`
для одного и того же физического момента.

**Тест:** `test_gps_galileo_identity_via_tai` в `src/time.rs`.

### I-9: Фиксированное смещение GPS–BeiDou

`BDT = GPS − 14 с` всегда. Это следует из `GPS+19 = BDT+33 = TAI`.

**Тест:** `test_gps_to_beidou_subtracts_14_seconds` в `src/time.rs`.

### I-10: Эпохальное смещение GLONASS–UTC

Эпоха GLONASS = 1995-12-31 21:00:00 UTC = 757 371 600 секунд от эпохи UTC
(1972-01-01). Это константа времени компиляции, проверяется так:

```rust
const _VERIFY_GLONASS_OFFSET: () = {
    assert!(GLONASS_FROM_UTC_EPOCH_NS / 1_000_000_000 == 757_371_600);
};
```

### I-11: Корректность двухпроходного алгоритма UTC → GPS

Двухпроходный алгоритм `utc_to_gps` корректен на всех 18 границах
високосных секунд эры GPS.
**Тесты:** `prop_all_18_leap_second_transitions_correct` в
`tests/prop_tests.rs` и отдельные тесты переходов в `src/leap.rs`.

### I-12: Точность roundtrip вне окна неоднозначности

Для любого `t: Time<Gps>`, которое **не** попадает в секундное окно
неоднозначности високосных секунд:
`gps_to_utc(utc_to_gps(t, ls), ls) == t`.

**Тест:** `prop_gps_utc_gps_roundtrip_for_all_samples` в
`tests/prop_tests.rs` (256 точек; окно неоднозначности пропускается через
`AmbiguousLeapSecond`).

## Инварианты памяти

### I-13: Нет выделения памяти в куче

`Time<S>` и `Duration` — типы `Copy` без реализации `Drop`.
`LeapSeconds::builtin()` возвращает `&'static LeapSeconds`, указывающий на
статический массив. Крейт `alloc` нигде не используется.

**Обеспечение:** `#![no_std]` в `lib.rs` без `extern crate alloc`. Тест
`all_conversions_are_stack_only` в `tests/no_std_compat.rs`.

### I-14: Размер 8 байт

`size_of::<Time<S>>() == 8` для всех `S: TimeScale`.

**Обеспечение:** модульный тест `test_size_equals_u64` выполняется в CI через
задачу `type-sizes` в `.github/workflows/embedded.yml`.

## Инварианты безопасности

### I-15: Нет unsafe-кода

`#![forbid(unsafe_code)]` в `lib.rs`. Любая попытка добавить unsafe-код
является ошибкой компиляции, а не предупреждением.

**Проверка в CI:** `grep -n "forbid(unsafe_code)" src/lib.rs` в задаче `lint`.

### I-16: Нет отсутствующей документации

`#![deny(missing_docs)]` в `lib.rs`. Каждый публичный элемент обязан иметь
документацию.

**Проверка в CI:** `cargo clippy -- -D warnings` в задаче `lint`.
